# Forge 2.0 Plan 4 — Agent Containers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run every agent session in its own container without Docker socket access; keep constant Ops communication; kill on heartbeat miss, idle timeout, or wall-clock max; hybrid secrets (git+Ops injected; others via audited Ops request).

**Architecture:** Forge (privileged) creates an agent container per session, injects bootstrap env, clones the project branch (GitHub interim until Plan 5), runs Cursor agent CLI inside. Agent posts heartbeats/events/secrets requests to Ops. A reconciler kills and fails sessions that violate policy. No `docker.sock` mount into agent containers.

**Tech Stack:** TypeScript, Vitest, Podman/Docker API via existing `docker-runtime.ts`, agent image Dockerfile, Ops routes, `agent-runner.ts` refactor.

## Global Constraints

- Spec defaults: heartbeat 10s, miss threshold 3, idle 30m, wall-clock 2h
- Agents: **no Docker socket**; git + Ops only
- Hybrid secrets: inject git creds + `FORGE_OPS_API_TOKEN` + `FORGE_OPS_API_BASE` + heartbeat config only
- Prefer agent→Forge event POST (UI must not depend on docker logs)
- Bootstrap Forgefile mode (Plan 1): restricted Ops until valid Forgefile
- Interim clone may still use GitHub until Plan 5
- Never mount host docker sock into agent; never run Forge `./deploy.sh` from agents
- `./build.sh --skip-install` + `./test.sh` before finish
