# Forge 2.0 Consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete 1.x twins so Forge 2.0 is the only codepath: authenticated edge, one session machine, containers-only agents, one deploy façade, Forge git host, Forgefile-owned Caddy, thin surfaces.

**Architecture:** Domain modules own transitions (`agent-session-machine`), deploys (`project-deploy`), remotes (`git-workspace` + `github-import`), and Caddy (`service-caddy`). HTTP routes are auth wrappers. Sidecar self-update stays an internal strategy behind `deployProject`.

**Tech Stack:** TypeScript, Next.js App Router, Drizzle/SQLite, Vitest, existing Forge lib tests.

## Global Constraints

- Pillars: RELIABLE, EXTENSIBLE, SECURE, PERFORMANT — no new special-case forks.
- Never run Forge `./deploy.sh`; redeploy via Ops/UI.
- `./build.sh --skip-install` then `./test.sh` (or `FORGE_LIVE_SMOKE=0 FORGE_UI_E2E=0 ./test.sh`) before finishing a slice.
- Touched god files must end under 1000 lines.
- Keep `--network host` + `--user 0:0`; no docker.sock.
- Spec: `docs/superpowers/specs/2026-09-15-forge-2.0-consolidation-design.md`
