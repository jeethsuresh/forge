# Forge 2.0 Plan 5 — Git Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Forge the primary git host (smart HTTP + SSH): UI can create new projects seeded with the annotated Forgefile template, and existing GitHub repos can be imported once into Forge bare repositories.

**Architecture:** Bare repos under `/data/git/<slug>.git`. `git_repositories` table links to `projects`. Smart HTTP served by Next route with session/Ops/agent token auth. SSH via git-shell/authorized_keys managed in Global settings (or sshd sidecar). `post-receive` hook notifies Forge for Forgefile pickup + auto-deploy. After import/create, clone URL is Forge; GitHub is not required for day-to-day.

**Tech Stack:** TypeScript, `git` CLI, Vitest, existing auth (iron-session + Ops tokens), Caddy optional path for `/git`, Podman for optional ssh sidecar.

## Global Constraints

- Spec: Forge is primary origin; GitHub **one-shot import** only (no dual ongoing sync in v1)
- New projects seed README + `docs/forgefile.template.yml` content as `Forgefile`
- Transports: smart HTTP + SSH
- Working copies: `/data/repos/...` for privileged jobs; agents clone via HTTP with session token
- `post-receive` → `projectForgefile` + wake auto_deploy targets
- `./build.sh --skip-install` + `./test.sh` before finish
- Never run Forge `./deploy.sh` from agents
