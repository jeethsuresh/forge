# Forge 2.0 Plan 2 — Service Directory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface every deploy-target port in a fleet service directory with declared+observed state, basic health probes, and Caddy route scaffolding for public+subdomain ports.

**Architecture:** On Forgefile projection, upsert `service_directory` rows from `deploy_targets.ports`. After successful deploy, observe bound ports from compose/docker and sync public subdomain routes via existing Caddy helpers. A boot ticker probes health endpoints and updates status only (no auto-redeploy).

**Tech Stack:** TypeScript, Vitest, SQLite/Drizzle, existing `caddy-config.ts` / `project-routing.ts` / `docker.ts`, `HomeCommandCenter.tsx`.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-12-forge-2.0-design.md`
- Depends on Plan 1: `deploy_targets`, `projectForgefile()`, valid Forgefile gate
- Private ports: directory only (no Caddy)
- Public + subdomain: scaffold/sync Caddy; on sync failure set route error — never claim URL live
- Host port uniqueness across all directory rows / targets
- Health failures: UI/API only; no auto-redeploy in v1
- Defaults: health interval 30s (or Forgefile `ports[].health.interval_seconds`)
- Never run Forge `./deploy.sh` from agents; `./build.sh --skip-install` + `./test.sh` before finish

**Files:**
- Create: `src/lib/service-caddy.ts`, `src/lib/service-caddy.test.ts`
- Modify: `src/lib/project-routing.ts` as needed to accept per-target routes
- Call from deploy success after observe

**Interfaces:**
- `export async function syncDeployTargetCaddyRoutes(projectId: string, deployTarget: string): Promise<void>`
- For each public port with subdomain: build host ` {subdomain}.{forgeDomain} ` using existing domain config; upstream `127.0.0.1:{boundPort||port}`; call existing upsert helpers
- On failure: `setServiceRouteStatus(..., "error", message)`; do not set a public URL as live
- On success: `routeStatus=synced`, set `url`
- Private ports: `routeStatus=none`
