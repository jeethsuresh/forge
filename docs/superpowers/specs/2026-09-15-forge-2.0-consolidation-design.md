# Forge 2.0 consolidation (design)

Date: 2026-09-15  
Status: approved for implementation  
Approach: delete 1.x twins; keep one codepath per concept  
Related: `docs/superpowers/specs/2026-08-12-forge-2.0-design.md` (original 2.0), architecture audit 2026-09-15

## Problem

Forge 2.0 shipped as a *second* implementation beside 1.x: process agents next to containers, GitHub remotes next to Forge git, `forge_updates` next to `deployments`, managed Caddy JSON next to Forgefile service directory, filesystem release JSON next to SQLite. Several host-network endpoints are unauthenticated. Agent reconcile can fail a healthy session when a container row is removed after a successful turn.

## North star

Every change is judged against four pillars:

- **RELIABLE** — one status machine, one deploy history, no false-failed sessions
- **EXTENSIBLE** — Forgefile, Forge git, and service directory are the extension points
- **SECURE** — authz is explicit; matcher tricks are not a security boundary
- **PERFORMANT** — fewer dual paths, fewer polls of dead twins, files under 1k lines when touched

Pillar test: does this slice make the remaining path inevitable, or add another special case?

## Goals

1. Close unauthenticated recover and Caddy log read; explicit middleware allowlist.
2. One agent session transition module; containers-only runtime with Cursor `--resume`.
3. One `deployProject()` façade; `deployments` is the only history; release pins in SQLite.
4. Migrate leftover GitHub-origin projects into Forge bare repos; shrink git helpers to import-only GitHub.
5. Forgefile service directory is the only writer of project public Caddy routes.
6. Thin dual API wrappers; split god UI files under 1k lines. No visual redesign.

## Non-goals

- Job-queue platform rewrite
- True network-namespace sandbox (keep `--network host` + `--user 0:0` as the documented Podman bind-mount constraint)
- UI restyle / design-system work
- S3 artifact storage
- Dual GitHub+Forge ongoing sync
- Running Forge’s own `./deploy.sh` (Ops/UI Redeploy only)

## Locked decisions

| Topic | Choice |
|-------|--------|
| GitHub leftovers | Import into Forge bare repos as part of this work |
| GitHub after migrate | One-shot Import GitHub only (`github-import.ts`) |
| Forge deploy strategy | Sidecar `startForgeUpdate` remains **internal** |
| Deploy history | `deployments` rows only (Forge uses `deployTarget: "self"`) |
| Release pins | SQLite `release_pins`; sidecar JSON is a working copy reconciled into DB |
| Agent runtime | Containers only in production; tests inject a fake runner |
| Session status | Only `agent-session-machine.ts` writes `agent_sessions.status` |
| Operator stop | One `operator_stop` event with reason enum (not log-string matching) |
| Reconcile | Never fail `running`/`deploying` solely because container is `stopped`/`removed` |
| Caddy for apps | Service directory from Forgefile is the only writer |
| `host_port` | Compose `HOST_PORT`; projected from Forgefile public port when present |
| Global Caddy | Remains for non-project routes |
| Forge identity | `gitRepositoryId` and/or `clonePath === forgeSourceDir()` — not `parseGithubRepo(FORGE_SELF_REPO)` |
| Isolation | No docker.sock; no new sandbox story this round |

## Architecture

```
Browser  --session-->  /api/projects/*  ─┐
Agent    --fos.*----->  /api/ops/*       ─┼─► domain lib ─► SQLite
Git      --fgc/fos--->  /api/git/*       ─┘         │
Sidecar  --ops token->  /api/forge/recover          ▼
                                              Podman + Forge git + Caddy
```

Domain modules (canonical):

- `project-deploy.ts` — `deployProject` / `rollbackProject`
- `agent-session-machine.ts` — `transition(sessionId, event)`
- `agent-container.ts` — docker run/stop/remove (no sock)
- `git-workspace.ts` — clone/fetch/branch/commit against Forge remotes
- `github-import.ts` — one-shot GitHub import
- `service-caddy.ts` — project public routes
- `release-pins.ts` — SQLite pins; reconcile sidecar file

## Slice 1 — SECURE (edge)

### Public paths (middleware)

Allow without iron-session:

- `/login`, `/api/auth/login`
- `/api/forge/health`
- `/api/ops` prefix (token auth in-route)
- `/api/git` prefix (git HTTP + hook secret in-route)
- `/api/caddy/logs/ingest` (ingest token in-route)
- `/_next`, `/favicon`

Not public: `/api/forge/recover`, `GET /api/caddy/logs`.

Matcher: explicit prefixes above plus static assets. Do **not** skip every path containing `.`.

### Recover

`POST /api/forge/recover` requires Ops global token or a recover secret (`FORGE_RECOVER_SECRET` falling back to `FORGE_OPS_API_TOKEN`). Sidecar `attempt_forge_recovery` sends `Authorization: Bearer`. Unauthenticated → 401.

### Logs GET

Requires dashboard session (route-level `getSession` plus middleware).

### Other

- Global Ops token compare: `timingSafeEqual` on equal-length buffers (reject length mismatch first).
- Git hook secret: env or ops session secret; `"forge-git-hook-dev"` only when `FORGE_DB_PATH=:memory:`. Hook curl retries once; failures logged, not silently `|| true`.
- SQLite `busy_timeout = 5000`.
- Gitignore `/releases/`.

## Slice 2 — RELIABLE (session machine)

`transition(sessionId, event)` is the only writer of `agent_sessions.status`.

Events: `queue` | `start` | `run` | `turn_complete` | `deploy_start` | `deploy_ok` | `deploy_fail` | `operator_stop` | `kill` | `fail` | `archive`.

`operator_stop.reason`: `end` | `stop` | `cancel` | `recovery_abort`.

`kill.reason`: `heartbeat_miss` | `idle_timeout` | `wall_clock`.

Reconcile: fail a `running`/`deploying` session with container `stopped`/`removed` only if `killReason` is set, or the turn is incomplete **and** no runtime is active. Successful turn: `turn_complete` then container remove.

Rename `hasActiveProcess` → `hasActiveRuntime`.

Split `agent-runner.ts` into create/queue, turn execution, deploy-after-agent. Display parsing stays in `agent-stream.ts`.

HTTP paths for end/stop/cancel may remain; they all call `operator_stop`.

## Slice 3 — containers-only

Delete production `runAgentTurnProcess`, `activeAgentProcesses`, `FORGE_AGENT_RUNTIME`. Tests inject a runner; they do not spawn a host child.

Entrypoint passes `--resume` when `FORGE_CURSOR_SESSION_ID` is set. Event ingest persists `cursorSessionId`.

Keep `assertNoDockerSockMount`.

## Slice 4 — one deploy façade

`deployProject({ projectId, branch, target, trigger, authorizeActiveSession? })`:

- Non-Forge → `runDeployment` (Forgefile fail-closed)
- Forge → `startForgeUpdate` internally

Routes import `deployProject` / `rollbackProject` only — not `startForgeUpdate`.

Every Forge update inserts `deployments` with `deployTarget: "self"`. Migrate `forge_updates` rows into `deployments`. UI/Ops read `deployments`. Drop `forge_updates` as source of truth after backfill (keep table until a later cleanup if live rows exist, but stop writing).

`release_pins` table: `project_id` PK, `stable_commit_sha`, `rollback_commit_sha`, `image_tag`, `updated_at`. Sidecar may write `/data/forge-release.json` for shell cutover; Node reconciles into `release_pins` on success/fail/recover. UI/Ops read SQLite.

Forgefile for Forge: document deploy as Ops/self-update, not `./deploy.sh`. Delete unreachable Forge cutover inside `runComposeReleaseDeploy` if public APIs never call it.

Forge identity: `gitRepositoryId` and `clonePath === forgeSourceDir()`.

## Slice 5 — Forge git host

On startup (and a callable `migrateGithubOriginProjects()`): each project with `githubRepo` set and `gitRepositoryId` null is imported to `/data/git/<slug>.git`, `gitRepositoryId` set, working clone remotes pointed at Forge. Includes Forge itself.

After migrate:

- `projectRemoteUrl` / `projectAgentCloneUrl` require a Forge repo
- GitHub clone only inside `github-import.ts`
- Self-update fetches from Forge origin / `/data/forge-source`
- Push uses the Forge remote, never implicit GitHub `origin`

`github.ts` becomes import-only (or is replaced by `github-import.ts` + re-exports during transition). Workspace git lives in `git-workspace.ts`.

## Slice 6 — Caddy from Forgefile

`syncDeployTargetCaddyRoutes` after Forgefile projection and successful deploy is the only writer of project public routes.

Port uniqueness: `service_directory` **and** `projects.host_port`, both directions.

Project Settings: read-only declared/observed routes; optional link of unmanaged Caddy routes for log filtering. Remove the managed-route form that writes independent `caddy_route_json` policy. Global Caddy editor remains.

`host_port` / `HOST_PORT` projected from the Forgefile public port when present.

Prefer post-receive auto_deploy; 60s watcher is backup only.

## Slice 7 — surfaces

Dashboard vs Ops: auth + audit wrap around shared handlers (`ops-api-route.ts` pattern).

Split `AgentWorkspace.tsx` into stream hook, action bar, branch rail, chat. Split `ProjectStudio.tsx` into mode routers + shared poll hook. No visual redesign. Touched files must not stay over 1000 lines.

## Errors

- Unauthenticated recover / Caddy GET → 401
- Missing Forge git after migrate → fail closed on clone/deploy/agent
- Invalid session transition → throw; caller maps to 409
- Port conflict across host_port and service directory → Forgefile invalid / routing PATCH 409

## Tests

- Middleware/public-path unit tests: recover and logs GET not public; git/ops/ingest still public
- Recover 401 without token; 200/404 with token
- Timing-safe global Ops token
- Hook secret: no `forge-git-hook-dev` unless `:memory:`
- Session machine: legal transitions; reconcile does not fail deploying after normal remove
- Container resume env passed when cursorSessionId set
- `deployProject` used by both route files (source invariant + behavior)
- Git migrate: GitHub-origin project gains `gitRepositoryId`; `projectRemoteUrl` is bare path
- Caddy: hostPortConflict sees service directory ports and vice versa
- UI splits: files under 1000 lines (assert in a small hygiene test or CI grep)

## Out of scope recap

Job queue, network sandbox, UI restyle, S3, GitHub mirror-out, Forge `./deploy.sh`.
